## 21. Completion Requirements

A feature is complete only when:

1. Its user interface works.
2. Its input is validated.
3. Its actual processing works.
4. Its output is useful.
5. Errors are handled clearly.
6. Save or export works where applicable.
7. Mobile usability is checked.
8. Acceptance tests pass.
9. Existing features pass regression tests.
10. Production behavior is verified where applicable.

## 22. Development Rules

- Preserve every approved feature.
- Update this registry as work progresses.
- Never claim untested functionality is complete.
- Keep API keys out of frontend code.
- Review free-tier limits and costs.
- Use small, reversible GitHub commits.
- Test after meaningful changes.
- Keep the old STORY-AI-PRO project separate.
- Build one complete workflow at a time.
